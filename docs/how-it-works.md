# 동작 원리와 보안

방법 A·B가 서버에서 무엇을 바꾸는지, 이미지를 어떻게 지키는지, 무엇이 안 되는지, 접을 때는 어떻게 하는지를 적었습니다. 설치와 되돌리기 절차는 [설치 문서](install.md)에 있습니다.

## 동작 원리

Coolify가 원래 제공하는 두 곳만 바꿉니다. 업데이트·설치 스크립트와 compose 본체는 공식 CDN 것을 그대로 씁니다.

- `docker-compose.custom.yml`
  - 공식 `upgrade.sh`는 이 파일이 있으면 compose에 함께 넣습니다.
  - 우리 구간은 coolify 서비스의 이미지만 `<저장소>:${LATEST_IMAGE}`로 바꿉니다.
  - 그래서 공식 업데이트가 새 버전 번호를 넘기면, 같은 번호의 한국어판을 받습니다.
- `.env`의 `VERSIONS_URL`
  - Coolify가 새 버전을 확인하는 주소입니다.
  - 우리 미러는 공식 `versions.json`을 그대로 복사하고 `coolify.v4.version`만 바꿉니다.
  - 한국어판(또는 아래 통과 태그)이 있는 버전만 업데이트로 보입니다. helper·sentinel·traefik 값은 공식 값을 그대로 따릅니다.
- `.env`의 `COOLIFY_LOCALE=ko`는 화면 언어입니다. 서버 전체에 적용됩니다.

## 보안 모델

- 이미지
  - 같은 버전 공식 이미지(다이제스트 고정) 위에 화면 파일만 덮습니다.
  - 덮는 경로: `app/`, `resources/views/`, `config/`, `bootstrap/helpers/`, `lang-default/`
  - 발행 전에 층 목록을 검사해 허용 경로 밖의 파일, 링크, 삭제 표시가 있으면 내지 않습니다.
- 발행
  - 사람이 승인한 뒤에만 발행합니다.
  - 이미지에는 cosign 서명과 출처 증명을 붙입니다. 서명 방식(키 기반 추천: 키리스는 서명한 사람의 이메일이 공개 로그에 영구히 남는다)은 공개 전에 정합니다.
  - 확인 명령은 [설치 문서의 이미지 서명 확인](install.md#이미지-서명-확인)에 있습니다.
  - 빌드 서버에는 발행 토큰·서명 키를 두지 않습니다.
- 스크립트
  - 설치·제거 때만 돕니다. 업데이트 경로에는 들어가지 않습니다.
  - 표시 구간 밖의 내용은 바꾸지 않습니다.
  - 백업 폴더에는 `.env` 사본(비밀값 포함)이 있으므로 root만 읽게 둡니다(0700).
- 보안 패치 지연
  - 상류에 새 버전이 나오면 그날 한국어판을 만듭니다.
  - 2일 안에 만들지 못하면 "통과 태그"를 냅니다. 공식 이미지를 그대로 우리 이름으로 낸 태그입니다. 그 버전은 영어로 보이지만 업데이트는 막히지 않습니다.
- 미러가 3일 넘게 갱신되지 않거나 상류보다 7일 넘게 뒤처지면, 대시보드에 되돌리는 방법을 알리는 배너가 뜹니다.
- 미러 값 검사
  - Coolify는 미러의 helper·sentinel·Coolify 버전 값을 셸 명령에 넣습니다.
  - 미러를 만들 때와 한국어판 이미지 안에서 두 번, 그 값이 영숫자와 `.` `+` `-`만으로 된 버전 꼴인지 검사합니다.
  - 꼴이 맞지 않으면 미러는 갱신을 멈추고, 이미지는 그 응답을 받지 않은 것으로 처리해 업데이트를 미룹니다.

## 한계

- 같은 버전 번호로 다시 배포할 수 없습니다.
  - Coolify는 지금과 같은 번호를 업데이트로 보지 않고 낮은 번호로는 내려가지 않습니다.
  - 그래서 이미지 핫픽스가 없습니다. 번역 수정은 다음 상류 버전에 들어갑니다.
- 급한 번역 수정은 언어 파일 볼륨으로 바꿔 끼웁니다.
  - 이미지에는 기본 언어 파일(`/var/www/html/lang-default/ko.json`)이 들어 있습니다.
  - 볼륨 `/var/www/html/lang-runtime/ko.json`이 있으면 그 파일을 먼저 읽습니다. 파일이 깨졌으면 기본값으로, 그것도 없으면 영어로 뜹니다.
  - 새 언어 파일: `https://coolify-ko.geonwoo.dev/lang/ko.json`(sha256은 `https://coolify-ko.geonwoo.dev/lang/manifest.json`)
  - `docker-compose.custom.yml`의 우리 구간 안, `image:` 줄 바로 다음에 같은 들여쓰기로 넣습니다. `install`을 다시 돌리면 이 줄이 지워지므로 다시 넣어야 합니다.

    ```yaml
        volumes:
          - /data/coolify/coolify-ko/lang:/var/www/html/lang-runtime:ro
    ```

- amd64와 arm64 이미지를 냅니다. 다른 아키텍처는 지원하지 않습니다.
- 언어는 서버 전체에 하나입니다. 사용자별로 고를 수 없습니다.
- 삭제 확인 문구(`Confirm Deletion` 등)와 사용자 데이터는 번역하지 않습니다. 입력해야 하는 문구가 영어 그대로여야 기능이 깨지지 않습니다.

## 종료 정책

관리자가 그만두기로 하면 다음 순서로 접습니다. 발행한 태그는 지우지 않습니다(재설치에 필요합니다).

1. 미러의 Coolify 버전은 마지막으로 발행한 버전에 고정하고 미러는 호스팅이 허락하는 한 그대로 둡니다.
   - 미러를 공식 `versions.json` 그대로 바꾸면 안 됩니다. 서버의 `docker-compose.custom.yml`이 우리 이미지 태그를 가리키므로, 우리가 내지 않은 새 버전을 알리면 업데이트가 매시간 조용히 실패합니다.
2. [README](../README.md)에 종료를 알립니다.
3. 상류에 새 버전이 나온 지 7일이 지나면, 대시보드 배너가 "한국어판이 따라가지 못함"과 되돌리기 명령을 보여 줍니다.

종료한 뒤에는 쓰던 서버가 더는 업데이트되지 않습니다. [되돌리기 명령(`uninstall`)](install.md#되돌리기)을 실행해 공식판으로 돌아가야 보안 패치를 받습니다.

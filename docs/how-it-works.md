# 동작 원리와 보안

이 문서는 방법 A와 B가 서버에서 변경하는 설정, 컨테이너 이미지의 무결성과 보안을 유지하는 방식, 기술적 제약 사항, 그리고 프로젝트 운영 종료 시의 대응 절차를 다룹니다. 설치 및 복구 절차는 [설치 문서](install.md)를 참고하세요.

## 동작 원리

Coolify가 공식적으로 제공하는 확장 포인트(Hook) 두 곳만 활용합니다. 업데이트 및 설치 스크립트, 그리고 Docker Compose 구성 본체는 공식 CDN의 원본을 그대로 사용합니다.

- `docker-compose.custom.yml`
  - 공식 `upgrade.sh`는 이 파일이 존재하면 Compose 실행 옵션에 자동으로 함께 포함합니다.
  - 한국어 패치 구간에서는 `coolify` 서비스의 컨테이너 이미지만 `<저장소>:${LATEST_IMAGE}`로 재정의합니다.
  - 따라서 공식 업데이트 프로세스가 새 버전 번호를 전달하면, 동일한 버전 번호의 한국어판 이미지를 자동으로 다운로드합니다.
- `.env`의 `VERSIONS_URL`
  - Coolify 대시보드가 새로운 릴리스 버전을 확인하는 주소입니다.
  - 한국어 미러 서버는 공식 `versions.json`을 그대로 복사하여 제공하되, `coolify.v4.version` 항목만 한국어판 최신 버전으로 제공합니다.
  - 이에 따라 한국어판(또는 아래에서 설명하는 패스스루 태그)이 준비된 버전만 업데이트 알림으로 노출됩니다. helper, sentinel, traefik 등의 보조 컴포넌트 버전은 공식 값을 그대로 유지합니다.
- `.env`의 `COOLIFY_LOCALE=ko`는 대시보드 화면의 기본 언어 설정이며, 서버 전체에 적용됩니다.

## 보안 모델

- 컨테이너 이미지
  - 동일 버전의 공식 이미지(고유 다이제스트 기반 고정) 위에 UI 관련 파일만 덮어씌웁니다.
  - 변경 허용 경로: `app/`, `resources/views/`, `config/`, `bootstrap/helpers/`, `lang-default/`
  - 배포 전 이미지 레이어 목록을 검사하여, 허용된 경로 외의 파일 변경, 심볼릭 링크, 파일 삭제 표시가 발견되면 배포를 즉시 차단합니다.
- 배포 절차
  - 자동화 빌드 후 관리자가 수동으로 검토하고 승인한 경우에만 배포합니다.
  - 이미지에는 cosign 디지털 서명과 빌드 출처 증명(Attestation)을 함께 첨부합니다. 서명 방식(키 기반 권장: 키리스 방식은 서명자의 이메일 주소가 공개 투명성 로그에 영구히 남음)은 공개 배포 전 확정합니다.
  - 확인 명령은 [설치 문서의 이미지 서명 확인](install.md#이미지-서명-확인)에 있습니다.
  - 빌드 서버 환경에는 배포 토큰이나 서명 키를 영구 보관하지 않아 침해 사고를 예방합니다.
  - 미러는 6시간마다 갱신하기 전에, 발행한 모든 버전 태그가 [발행 기록](../releases/published.json)의 다이제스트를 그대로 가리키는지 레지스트리에서 확인합니다. 다르거나 태그가 없으면 미러 갱신을 멈추고 관리자에게 즉시 알립니다.
- 설치 스크립트
  - 설치 및 제거 시점에만 단발성으로 실행되며, 일상적인 업데이트 과정에는 관여하지 않습니다.
  - 주석으로 표시된 전용 구간 외의 내용은 일절 수정하지 않습니다.
  - 백업 디렉토리에는 민감한 환경 변수가 포함된 `.env` 사본이 보관되므로, root 사용자만 접근할 수 있도록 권한을 엄격히 제한(0700)합니다.
- 업스트림 보안 패치 지연 방지
  - 업스트림(공식 Coolify)에 새 버전이 릴리스되면 당일 내로 한국어판 빌드를 생성합니다.
  - 2일(48시간) 이내에 한국어판을 완성하지 못할 경우 '패스스루(Pass-through) 태그'를 배포합니다. 이는 공식 이미지를 그대로 우리 이미지 이름으로 재발행한 태그로, 해당 버전에서는 화면이 일시적으로 영어로 표시되지만 긴급 보안 업데이트가 차단되는 현상을 방지합니다.
  - 미러 정보가 3일 넘게 갱신되지 않거나 업스트림 릴리스보다 7일 이상 뒤처질 경우, 대시보드 상단에 공식 버전 복구 방법을 알리는 안내 배너가 표시됩니다.
- 미러 응답 값 검증 (명령어 주입 방지)
  - Coolify는 미러에서 받아온 helper, sentinel, Coolify 버전 문자열을 셸 명령어 파라미터로 전달합니다.
  - 따라서 미러를 생성할 때와 한국어판 이미지 내부에서 실행될 때 두 차례에 걸쳐, 해당 값들이 영숫자와 `.` `+` `-` 기호로만 이루어진 안전한 버전 형식인지 정규식으로 검증합니다.
  - 규격에 맞지 않는 문자 패턴이 감지되면 미러 갱신을 즉시 중단하며, 컨테이너 또한 해당 응답을 수용하지 않고 업데이트를 안전하게 보류합니다.

## 한계

- 동일 버전 번호 재배포 불가
  - Coolify는 현재 설치된 버전과 동일한 번호를 업데이트 대상으로 인식하지 않으며, 더 낮은 번호로의 다운그레이드도 허용하지 않습니다.
  - 따라서 동일 버전에 대한 컨테이너 이미지 핫픽스를 제공하기 어렵습니다. 일반적인 번역 수정 사항은 다음 업스트림 릴리스 버전에 함께 반영됩니다.
- 긴급 번역 수정(핫픽스) 적용 방법
  - 이미지 내부에는 기본 언어 파일(`/var/www/html/lang-default/ko.json`)이 기본 내장되어 있습니다.
  - 호스트 볼륨으로 마운트된 `/var/www/html/lang-runtime/ko.json` 파일이 존재할 경우 해당 파일을 최우선으로 로드합니다. 파일이 손상되었거나 파싱에 실패하면 기본 번역으로 fallback되며, 기본 번역마저 없으면 영어로 표시됩니다.
  - 최신 언어 파일 주소: `https://coolify-ko.geonwoo.dev/lang/ko.json` (SHA-256 검증: `https://coolify-ko.geonwoo.dev/lang/manifest.json`)
  - 적용 시 `docker-compose.custom.yml`의 패치 구간 내부, `image:` 줄 바로 다음에 동일한 들여쓰기로 볼륨을 추가합니다(단, `install` 명령을 재실행하면 패치 구간이 초기화되므로 이 설정을 다시 추가해야 합니다).

    ```yaml
        volumes:
          - /data/coolify/coolify-ko/lang:/var/www/html/lang-runtime:ro
    ```

- amd64 및 arm64 이미지만 제공하며, 다른 아키텍처는 지원하지 않습니다.
- 언어 설정은 서버 인스턴스 전체에 일괄 적용되며, 사용자 계정별로 개별 선택할 수는 없습니다.
- 삭제 확인 문구(`Confirm Deletion` 등 안전 검증을 위해 직접 입력해야 하는 프롬프트)와 사용자가 등록한 데이터는 번역하지 않습니다. 기능이 정상 작동하려면 사용자가 입력하는 문구가 영문 원본과 일치해야 하기 때문입니다.

## 종료 정책

프로젝트 운영을 종료하게 될 경우 다음 순서에 따라 순차적으로 마무리합니다. 기존에 배포된 이미지 태그는 컨테이너 재설치 등을 위해 삭제하지 않고 유지합니다.

1. 미러의 Coolify 버전을 마지막으로 배포된 버전에 고정하고, 미러 호스팅은 인프라가 허용하는 한 그대로 유지합니다.
   - 미러를 공식 `versions.json`으로 바로 변경해서는 안 됩니다. 서버의 `docker-compose.custom.yml`이 한국어판 이미지를 가리키고 있으므로, 빌드되지 않은 새 버전을 안내할 경우 매시간 백그라운드 업데이트가 조용히 실패하게 됩니다.
2. [README](../README.md)를 통해 서비스 종료를 공식 공지합니다.
3. 업스트림에 새 버전이 릴리스된 지 7일이 지나면, 대시보드 상단 배너에 한국어판 지원 종료 안내와 함께 공식 버전 복구 명령어가 표시됩니다.

종료한 뒤에는 사용 중인 서버가 더 이상 자동으로 업데이트되지 않습니다. 지속적인 보안 패치와 기능 지원을 받으려면 반드시 [되돌리기 가이드(`uninstall`)](install.md#되돌리기)를 참고하여 공식 버전으로 복구하시기 바랍니다.
